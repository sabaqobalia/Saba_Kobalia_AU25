What operations do the following functions perform: film_in_stock, film_not_in_stock, inventory_in_stock, get_customer_balance, inventory_held_by_customer, rewards_report, last_day?

The film_in_stock function takes a film_id and store_id as input, and returns the number of available copies for that film in that store. It uses the inventory table together with the inventory_in_stock function to count how many copies are in stock. The film_not_in_stock function does the opposite — it returns the number of unavailable copies in a specific store, again relying on the inventory_in_stock function. The inventory_in_stock function checks if a particular inventory item is available by determining whether it has never been rented or has been returned, using the rental table. The get_customer_balance function calculates the current balance for a given customer at a specified effective date. It includes rental fees for all previous rentals, one dollar for each day a rental is overdue, the replacement cost if a film is more than twice its rental duration overdue, and subtracts all payments made before the given date. The inventory_held_by_customer function identifies which customer currently has a particular inventory item rented. If the item is in stock, it returns NULL. The rewards_report function generates a list of customers who meet certain spending conditions over the previous month and qualify for a reward; it uses dynamic SQL and temporary tables. The last_day function returns the last day of the month for a given timestamp by calculating the first day of the next month and subtracting one day.

What does ‘last_updated’ function do? Where is it used?

The last_updated function is a trigger function that automatically updates the last_update timestamp column to the current time whenever a row is updated in a table. It ensures the record always reflects the latest modification time. This function is commonly attached to most tables in the database.

The tmpSQL variable in the rewards_report function stores dynamically constructed SQL queries as strings, which are later executed using the EXECUTE statement.
