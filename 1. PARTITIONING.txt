2. Create partition function for your tables.

CREATE OR REPLACE FUNCTION partition_sales_info() RETURNS trigger
as $$
BEGIN
IF (new.eventdate >= '2020-01-01'::DATE AND
new.eventdate < '2021-01-01'::DATE) THEN
INSERT INTO labs.sales_info_2020 VALUES (new.*) ;
ELSEIF (new.eventdate >= '2021-01-01'::DATE AND
new.eventdate < '2022-01-01'::DATE) then
INSERT INTO labs.sales_info_2021 VALUES (new.*) ;
ELSEIF (new.eventdate >= '2022-01-01'::DATE AND
new.eventdate < '2023-01-01'::DATE) then
INSERT INTO labs.sales_info_2022 VALUES (new.*) ;
ELSEIF (new.eventdate >= '2023-01-01'::DATE AND
new.eventdate < '2024-01-01'::DATE) then
INSERT INTO labs.sales_info_2023 VALUES (new.*) ;
ELSEIF (new.eventdate >= '2024-01-01'::DATE AND
new.eventdate < '2025-01-01'::DATE) then
INSERT INTO labs.sales_info_2024 VALUES (new.*);
ELSEIF (new.eventdate >= '2025-01-01'::DATE AND
new.eventdate < '2026-01-01'::DATE) then
INSERT INTO labs.sales_info_2025 VALUES (new.*);
ELSEIF (new.eventdate >= '2026-01-01'::DATE AND
new.eventdate < '2027-01-01'::DATE) then
INSERT INTO labs.sales_info_2026 VALUES (new.*);

ELSE
RAISE EXCEPTION 'Out of range';
END IF;
RETURN NULL;
END;
$$ language plpgsql;

3. Create trigger for your function and tables

CREATE TRIGGER partition_sales_info_trigger
BEFORE INSERT ON labs.sales_info
FOR EACH ROW EXECUTE PROCEDURE partition_sales_info();

6. Create table SALES_INFO_SIMPLE with the same structure as SALES_INFO but without
partitioning. Insert test data from the 5th step. Compare plans of different queries:

• Select all
when selecting * from inherited table, system scans all the child tables and appends them (sc_1)
when selecting * from simple table, system uses the simple sequential scan method (sc_2)

• Select with range of dates
when selecting from inherited table, system scans only the child tables that could possibly have values
we need and skips inappropriate partitions.
when selecting  from simple table, system uses the sequential scan + filter on the whole table.

• Select exact date
again, for inherited table, only the appropriate partition is scanned + parent table.
for simple table, regular scan + equality filter

• Count of all rows
inherited table : aggregates all child tables.
simple table: aggregates all rows from simple table.

• Count of rows with range of dates
same thing here.
in 1st case, parent table and the matching partition are scanned.
in 2nd case - whole table.
